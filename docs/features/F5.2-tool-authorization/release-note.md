# F5.2 — Release Note

## 概述

AI 助手写操作（预约 / 取消预约）补齐四关安全校验，并修复 AI 错误回复可能回显内部异常信息的问题。

## 变更点

- **角色授权**：`create_booking` / `cancel_booking` 仅允许学员角色调用；教师、管理员、无角色账号通过 AI 发起写操作时收到友好提示（403），且不会触发任何业务写入。
- **入参校验**：排期 ID、预约 ID 必须为正整数；取消原因为字符串且不超过 200 字，非法输入在 Tool 层被拒绝（400）。
- **身份校验**：未登录调用返回 401 引导登录。
- **信息安全**：Tool 不再吞掉并回显原始异常；未知错误统一回复"操作失败，请稍后重试或联系客服"，不泄露 SQL / 堆栈 / 内部消息。
- **附带修复**：`AgentRuntime` 补齐 `tenant_id` 构造参数，修复 AI router 传参与构造函数不匹配导致的 TypeError。

## 用户可见影响

- 学员使用 AI 预约/取消：体验不变，成功路径无变化。
- 非学员账号对 AI 说"预约/取消"：由原来的"以本人身份执行（可能成功或产生困惑错误）"变为明确提示"当前账号没有学员身份"。
- 任何 AI 错误回复不再包含技术性原始报错。

## 接口与兼容性

- `POST /api/v1/ai/chat` 请求/响应契约零变更；
- 无数据库结构变更、无配置项变更、无前端改动；
- 无需重新生成 api-types。

## 验证

- 新增授权测试 18 项全部通过；
- 业务异常友好映射 10 项全部通过（匹配且不泄露原文）；
- RBAC / 预约归属集成回归 27 项通过。

## 部署注意

- 纯后端发布，无前置数据迁移；
- 依赖既有 RBAC user_roles 数据正确（学员账号需具备 student 角色，与管理端角色体系一致）。
