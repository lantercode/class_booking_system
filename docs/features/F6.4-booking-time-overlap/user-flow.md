# F6.4 用户流程：预约跨排期时间段重叠校验

## 1. 学员预约主流程（含新增校验点）

```
学员选择排期 → POST /api/v1/bookings/
  │
  ├─ 1. 排期存在？           否 → 404 排期不存在
  ├─ 2. 排期状态 NORMAL？     否 → 400 该排期已取消或已完成
  ├─ 3. 容量未满？            否 → 400 该排期已约满
  ├─ 4. 时间窗口合法？        否 → 400 已开始 / 超两周 / 未开放 / 已截止
  ├─ 5. 同排期未重复预约？    否 → 400 您已预约该排期
  ├─ 6. 会员卡校验（D9）？    失败 → 400 卡相关错误（卡冲突优先）
  ├─ 7. 【新增】时间段不重叠？ 重叠 → 400 该时间段与您已约课程《X》（...）冲突
  ├─ 8. 占用名额 + 落库 + 扣次（同一事务）
  └─ 9. 201 预约成功
```

校验 7 位于 6 之后：会员卡冲突与时间冲突同时命中时，先提示卡冲突（与原型 `open-decisions.md` D10 解耦说明一致）。

## 2. 判定矩阵

| 已有预约状态 | 时间重叠 | 结果 |
|--------------|----------|------|
| `BOOKED` | 是 | **拒绝** |
| `BOOKED` | 否（含边界相接） | 放行 |
| `CHECKED_IN` | 是 | **拒绝** |
| `CHECKED_IN` | 否 | 放行 |
| `COMPLETED` / `NO_SHOW` / `CANCELLED` | 任意 | 放行（不参与判定） |
| 其他学员的预约 | 任意 | 放行（按 `student_id` 过滤） |
| 其他租户的预约 | 任意 | 放行（租户隔离） |

## 3. 边界示意（半开区间）

```
已有：  |---- 19:00 ---- 20:00 ----|
目标A：                20:00 ---- 21:00     → 相接，放行
目标B：           19:30 ---- 20:30          → 重叠，拒绝
目标C： 18:00 ---- 19:00                   → 相接，放行
目标D： 19:00 ---- 20:00                   → 完全重合，拒绝
```

## 4. 并发场景

同一学员在两个客户端同时提交两个重叠排期：

```
T1: BEGIN → 取得学员维度 advisory lock → 查重叠（无）
T2: BEGIN → 等待同一 advisory lock
T1: 占名额 + 插入预约 + COMMIT（释放锁）
T2: 取得锁 → 查重叠（命中 T1 的预约）→ 400，回滚
```

结果：至多一个成功，另一个收到业务错误，不产生双占。

## 5. 客户端表现（4 端）

| 端 | 表现 |
|----|------|
| student-web | 预约按钮触发 `POST /bookings`，收到 `code != 0` + HTTP 400，直接展示 `msg` |
| miniapp（学员） | 同上，`apps/miniapp/src/api/index.ts` 统一错误处理展示 `msg` |
| admin-web | 代约入口（如使用同一 Service 路径）同样收到 400；不新增 UI |
| teacher-web | 不涉及 |

> 无新增字段、无路由变更，前端零改动即可展示。

## 6. 异常与回滚

| 场景 | 行为 |
|------|------|
| 冲突命中 | `BusinessException` → 事务回滚；名额未占、卡未扣、无预约记录 |
| 查询异常 | 统一异常处理器返回信封错误，不回显 SQL/堆栈 |
| advisory lock 等待 | 由数据库在事务结束时自动释放；无显式 unlock |
