# F6.4 验收标准

> 分组：A 静态 / B 运行时功能 / C 权限与租户 / D 并发与幂等 / E 回归。
> 判定原则：未执行或不可验证的一律记 `NOT VERIFIED`，不得表述为 PASS。

## A. 静态

| ID | 标准 | 判定方式 |
|----|------|----------|
| A-1 | 应用可导入，无语法错误 | `py_compile` 全部改动文件 |
| A-2 | Lint 通过 | `ruff check` 改动文件 |
| A-3 | 分层：Router 不含业务判断，校验在 Service | 代码审查 |
| A-4 | Repository 继承 `TenantAwareRepository`，无裸 SQL 业务查询 | 代码审查（advisory lock 为锁原语，非业务查询） |
| A-5 | 无新增/删除端点，无 DTO 字段变更 | 代码审查 + 路由 diff |
| A-6 | 与 D9 卡校验解耦，不改 `validate_card_for_booking` / `deduct_credit` | 代码审查 |
| A-7 | 改动文件在白名单内 | mtime 清单 |

## B. 运行时功能

| ID | 场景 | 预期 |
|----|------|------|
| B-1 | 已有 `BOOKED` 19:00–20:00，预约 19:30–20:30 | 400，文案含课程名与时间段；无落库、无扣次、名额不变 |
| B-2 | 边界相接：已有 19:00–20:00，预约 20:00–21:00 | 201 成功 |
| B-3 | 已有 `CHECKED_IN` 且重叠 | 400 |
| B-4 | 已有 `COMPLETED` / `NO_SHOW` / `CANCELLED` 且重叠 | 201 成功（不参与判定） |
| B-5 | 非重叠排期 | 201 成功，行为与现状一致 |
| B-6 | 文案格式 | 「该时间段与您已约课程《X》（MM-DD HH:MM-HH:MM）冲突，无法预约」 |

## C. 权限与租户

| ID | 场景 | 预期 |
|----|------|------|
| C-1 | 未登录 | 401 |
| C-2 | 非学员角色调用 | 403 |
| C-3 | 跨租户：A 租户学员的预约不阻止 B 租户学员 | 201（租户隔离） |
| C-4 | 身份来自 `get_current_user`，不读请求体 | 代码审查 |

> C-3 需构造第二个租户或第二个租户的学员；若测试环境无第二租户，记 `NOT VERIFIED` 并说明。

## D. 并发与幂等

| ID | 场景 | 预期 |
|----|------|------|
| D-1 | 同一学员并发预约两个重叠排期 | 恰好 1 个 201、1 个 400；仅 1 条预约记录 |
| D-2 | 并发取消与预约重叠排期 | 不出现死锁；最终状态可解释 |
| D-3 | 重复提交同一排期 | 仍由既有唯一约束/查重拒绝，不产生重复 |

## E. 回归

| ID | 范围 |
|----|------|
| E-1 | 同排期重复预约、容量、时间窗口校验不回归 |
| E-2 | D9 会员卡有效期重叠与扣次/回补不回归（F6.3 定向用例） |
| E-3 | 签到/完成锁、取消排期回滚、RBAC、调度租户隔离回归 |

## 验收条件

- B-1 ~ B-6、D-1 全部 PASS 方可判定功能达成。
- C-3 若无法构造第二租户，必须显式记 `NOT VERIFIED` 并说明原因，不得静默通过。
- E-1 ~ E-3 至少执行与 booking/membership 相关的定向集。
