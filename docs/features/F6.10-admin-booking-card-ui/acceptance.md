## D. 前端功能验收

### D-1：预约管理页（admin-web）

| # | 用例 | 预期 |
|---|------|------|
| D-1.1 | 路由/菜单 | 侧边栏出现「预约管理」（排期管理之后），点击进入 `/bookings` |
| D-1.2 | 初始加载 | 进入页面显示 skeleton，数据返回后渲染表格 |
| D-1.3 | 空态 | 无数据时显示 `el-empty`「暂无预约数据」 |
| D-1.4 | 错误态 | 接口 500/断网时显示 `el-result` 错误 + 重试按钮，重试成功恢复 |
| D-1.5 | 排期筛选 | 输入排期 ID 查询，仅返回该排期预约 |
| D-1.6 | 状态多选 | 选中「待上课」「已签到」查询，请求 `status=1,3`，返回对应状态预约 |
| D-1.7 | 重置 | 点击重置清空筛选并重新查询全部 |
| D-1.8 | 列表字段 | 展示学员昵称+手机号、课程名、上课时间、教室、教师、状态 tag |
| D-1.9 | 状态 tag | display_status 1待上课(primary)/2已取消(info)/3上课中(warning)/4已完成(success)；status=5 未到场(danger) |
| D-1.10 | 签到按钮显隐 | 仅 status=1 行显示「签到」按钮 |
| D-1.11 | 完成按钮显隐 | 仅 status=3 行显示「完成」按钮 |
| D-1.12 | 代签到成功 | 点击签到 → 按钮 loading → 成功 toast → 该行 status 变 3，按钮切换为「完成」 |
| D-1.13 | 代签到失败 | 后端返回错误（如状态不允许），toast 后端 msg，按钮恢复，状态不变 |
| D-1.14 | 代完成成功 | 点击完成 → 成功 toast → 该行 status 变 4，操作列清空 |
| D-1.15 | 代完成失败 | 后端返回错误，toast msg，状态不变 |
| D-1.16 | 分页 | 翻页/改页大小重新请求，保留筛选条件，total 正确 |

### D-2：会员卡详情流水（admin-web）

| # | 用例 | 预期 |
|---|------|------|
| D-2.1 | 详情弹窗结构 | 点击「详情」打开弹窗，卡信息下方出现流水区块 |
| D-2.2 | 流水加载 | 打开弹窗自动按 card_id 调 `getTransactions`，loading 显示 skeleton |
| D-2.3 | 流水空态 | 无流水显示「暂无流水记录」 |
| D-2.4 | 流水错误态 | 查询失败显示错误提示 + 重试，不阻断卡详情展示 |
| D-2.5 | 流水列 | 展示操作类型（中文）、变动课时（正绿负红）、变动后余额、备注、时间 |
| D-2.6 | 操作类型映射 | issue→开卡 / consume→扣减 / restore→恢复 / recharge→充值 / refund→退款 / adjust→调整 / expire→过期清零 |
| D-2.7 | 流水分页 | 流水区块内分页可用，翻页重新请求 |
| D-2.8 | 关闭清空 | 关闭详情弹窗后流水状态清空，再次打开重新加载 |

### D-3：教师端完成按钮（teacher-web）

| # | 用例 | 预期 |
|---|------|------|
| D-3.1 | 按钮显隐 | 已签到学员（status==='attended'）显示「完成」按钮；待签到/已完成不显示 |
| D-3.2 | 完成成功 | 点击完成 → 按钮 loading → 成功 toast → 学员状态变 'completed'，完成按钮消失 |
| D-3.3 | 完成失败 | 后端返回错误，toast msg，状态不变，按钮恢复 |
| D-3.4 | 签到后联动 | 学员签到成功（status='attended'）后，「完成」按钮出现 |
