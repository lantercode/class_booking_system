# F5.3 — 用户流程

> Feature ID：F5.3
> 关联文档：[requirement.md](./requirement.md) / [acceptance.md](./acceptance.md)

## 1. 主流程：AI 对话正常响应

```
用户发送消息 → AgentRuntime.chat → 意图识别 → Tool 调用 → 格式化回复
  ↓
返回 AI 回复文本
```

- 无异常时行为不变。

---

## 2. 异常流程：已知业务异常

```
用户发送消息 → Tool 调用 Service → Service 抛出 BusinessException（中文 msg）
  ↓
AgentRuntime._handle_business_error 匹配中文关键词
  ↓
返回对应友好提示（含引导动作）
```

| 业务异常 | 友好提示示例 |
|---------|------------|
| 该排期已约满 | ❌ 该时段刚被约满 😢 回复「查排期」查看其他时段 |
| 重复预约 | ❌ 您已预约过此课程 回复「我的预约」查看 |
| 余额不足 | ❌ 课时余额不足 请联系前台充值 |
| 未找到预约 | ❌ 未找到对应的预约记录 可能已被取消 |
| 取消超时 | ❌ 已过可取消时限 如需帮助请联系前台 |
| 课程已开始 | ❌ 该课程已开始上课，暂不接受预约 |
| 预约过远 | ❌ 可预约范围仅限未来两周 |
| 已取消 | ❌ 该预约已被取消 |
| 状态非法 | ❌ 当前预约状态无法执行该操作 |

### 修复前

- 英文 key 匹配不到中文消息 → 全部走兜底 → 回显原始异常文本。

### 修复后

- 中文关键词命中 → 返回友好提示，且完整原始字符串不在输出中。

---

## 3. 异常流程：未知异常（兜底）

```
用户发送消息 → 抛出非业务异常（如 AttributeError、SQL 错误）
  ↓
AgentRuntime._handle_business_error 无关键词命中
  ↓
返回通用提示：⚠️ 操作失败，请稍后重试或联系客服
```

### 修复前

- 兜底返回 `f"⚠️ 处理请求时出错：{error}..."`，回显原始异常（可能含 SQL、堆栈等技术细节）。

### 修复后

- 兜底返回 `"⚠️ 操作失败，请稍后重试或联系客服"`，不含原始异常文本。

---

## 4. 防泄露约束

每条友好提示必须满足：

1. **关键词命中**：用户能理解发生了什么（如"约满"、"余额不足"）。
2. **原文不出现**：完整原始异常字符串不是输出的子串。

示例：
- 原始：`未找到该预约记录` → 输出：`未找到对应的预约记录`（"该预约记录" vs "对应的预约记录"，原文不是子串）✓
- 原始：`已超过取消截止时间` → 输出：`已过可取消时限`（原文不是子串）✓

---

## 5. Error 态与空状态

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 已知业务异常 | 回显原始中文消息 | 友好提示 + 引导动作 |
| 未知异常（含 SQL） | 回显原始异常（可能含技术细节） | 通用提示"操作失败，请稍后重试或联系客服" |

---

## 6. Permission / Authentication

- F5.3 不修改认证/授权逻辑。
- AI 端点仍需登录态（`get_current_user`），行为不变。
- 异常处理仅影响 AI 回复文本内容，不影响 HTTP 状态码（AI chat 端点始终返回 200 + 信封，异常体现在 `data.response` 文本中）。
