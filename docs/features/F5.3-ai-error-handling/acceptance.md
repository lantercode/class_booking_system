# F5.3 — Acceptance Criteria

> 每条可独立判定 PASS / FAIL。
> 主 AC 为 AC-1；全部 AC 通过方可进入 REVIEW / ACCEPTANCE。

## AC-1 业务异常映射为友好提示且不泄露原文（主验收标准）

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-1.1 | 输入"该排期已约满"→ 输出含"约满"且不含完整原文 | TC-01 |
| AC-1.2 | 输入"您已预约该排期，请勿重复预约"→ 输出含"已预约"且不含完整原文 | TC-02 |
| AC-1.3 | 输入"会员卡扣次失败，预约已撤销"→ 输出含"余额不足"且不含完整原文 | TC-03 |
| AC-1.4 | 输入"未找到该预约记录"→ 输出含"未找到"且不含完整原文 | TC-04 |
| AC-1.5 | 输入"已超过取消截止时间"→ 输出含"取消"且不含完整原文 | TC-05 |
| AC-1.6 | 输入"该课程已开始，无法预约"→ 输出含"已开始"且不含完整原文 | TC-06 |
| AC-1.7 | 输入"只能预约未来两周内的课程"→ 输出含"两周"且不含完整原文 | TC-07 |
| AC-1.8 | 输入"预约已取消"→ 输出含"取消"且不含完整原文 | TC-08 |
| AC-1.9 | 输入"当前预约状态无法签到"→ 输出含"状态"且不含完整原文 | TC-09 |

## AC-2 未知异常兜底不泄露

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-2.1 | 输入含 "SQL: SELECT * FROM" 的未知异常 → 输出含"操作失败"且**不含**原始字符串（含 SQL） | TC-10 |
| AC-2.2 | 兜底文本为"⚠️ 操作失败，请稍后重试或联系客服"，不含 `str(error)` 任何片段 | 代码审查 + TC-10 |

## AC-3 映射机制修正

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-3.1 | 不再使用英文枚举 key 匹配中文消息 | 代码审查（runtime.py 无 `error_map` / `.upper()`） |
| AC-3.2 | 使用中文关键词 `in` 子串匹配 | 代码审查 |

## AC-4 变更范围（静态）

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-4.1 | 实际修改文件 ⊆ {runtime.py, test_agent_runtime.py} | minimal-change-guard |
| AC-4.2 | 无契约变更：`/ai/chat` 请求/响应不变 | OpenAPI diff 审查 |
| AC-4.3 | 每个修改的 Python 文件通过 `python3 -m py_compile` | STATIC 记录 |
| AC-4.4 | diff 仅触及 `_handle_business_error` 方法体与新增测试函数 | diff 审查 |

## AC-5 回归

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-5.1 | `test_business_error_handling` 全部通过 | 运行命令 |
| AC-5.2 | AI chat 主流程不破坏（意图识别、Tool 调用链路） | 代码审查 + 可选 `test_agent_chat` |

## 判定规则

- 任何 AC-1.x FAIL → Feature 整体 FAIL
- AC-2 ~ AC-5 中出现 FAIL → NEEDS_FIX 回到 DEVELOPMENT
