# F6.6 用户流程：多卡默认推荐策略

## 1. 主流程（学员有可用卡）

1. 学员在排期详情点击「立即预约」，进入预约确认页（`scheduleId` 入参）。
2. 页面加载排期详情（课程名/时间/教室/教师）与课程类型映射。
3. 页面调用 `GET /api/v1/membership/recommend-card?schedule_id={id}`。
4. 后端：
   - 校验登录态与租户；
   - 读取排期（`ScheduleService.get_schedule_by_id`），不存在 → 404；
   - 读取当前学员全部会员卡；
   - 按 R-3~R-7 判定可用性；
   - 按 R-8 排序；
   - 返回 `available_cards` 与 `recommended_card_id`。
5. 页面按后端顺序渲染「使用会员卡」区域，默认选中 `recommended_card_id`。
6. 学员可点击卡片区域打开选择器，切换其他可用卡（仍为后端排序）。
7. 点击「确认预约」→ `POST /api/v1/bookings`（`schedule_id` + `membership_card_id`）→ 成功提示并返回上一页。

## 2. 异常流程

| 场景 | 后端行为 | 前端行为 |
|------|---------|---------|
| 未登录 / Token 失效 | 401 | 复用统一 401 刷新重放；失败清登录态跳登录页 |
| 排期不存在 / 跨租户 | 404 | Toast「加载失败」，返回上一页 |
| `schedule_id` 非法（≤0/非整数） | 422（Pydantic） | 参数错误提示并返回 |
| 网络失败 / 500 | 统一错误信封 | Toast「加载失败」，可重试（重新进入页面） |
| 有卡但全部被排除 | 200 + `recommended_card_id=null` + `message` | 展示空态与原因；「确认预约」禁用 |
| 学员无任何卡 | 200 + `message="您还没有会员卡"` | 展示空态；「确认预约」禁用 |
| 推荐后卡状态变化（并发冻结/过期） | 下单时 `create_booking` 拒绝 | 展示后端错误信息，返回后可重新加载推荐 |

## 3. 空状态

```
[使用会员卡]
  暂无可用的会员卡
  暂无可用会员卡：次卡已用完；会员卡已过期
[确认预约]（禁用）
```

- 空态直接渲染在「使用会员卡」卡片区（`selectedCard` 为空时也可见），必须显示后端 `message`；若 `message` 为空则回退「暂无可用的会员卡」。
- 选择器只在存在可用卡时可打开；空态不依赖弹窗，不出现空白弹窗。

## 4. Loading

- 页面级 loading 覆盖「课程信息 + 会员卡」加载阶段（保留现有 `loading` 状态）。
- 推荐请求与排期请求同一加载批次；任一失败进入错误态，不渲染半成品选卡区域。

## 5. Error

- 不使用前端本地规则兜底推荐（避免重新引入第二套规则）。
- 错误一律以 Toast 呈现，文案取后端 `msg`；不回显内部异常。
- 页面保留「取消」返回能力。

## 6. Success

- 默认选中卡高亮（radio 选中）。
- 卡片展示：产品名/卡类型、剩余次数或剩余天数、适用范围。
- 排序与后端一致：临近过期优先、次卡剩余少优先、同分先发放。
- 无「推荐」额外角标（本版不加视觉新元素，沿用现有选卡 UI）。

## 7. 权限与认证

| 项 | 规则 |
|----|------|
| 认证 | 必须登录，`Depends(get_current_user)` |
| 授权 | 只读本人卡，不提供他人 `student_id` 入参；无需管理权限 |
| 租户 | 排期查询走租户感知 Service；跨租户排期 → 404 |
| 越权 | 无法通过参数读取他人卡；`current_user.user_id` 唯一来源 |
| 数据最小化 | 复用 `MembershipCardResponse`，不新增敏感字段 |
