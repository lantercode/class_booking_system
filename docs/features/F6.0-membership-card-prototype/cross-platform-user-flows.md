# F6.0 跨端端到端用户流程（Cross-Platform User Flows）

> 日期：2026-10-09
> 约定：每条流程含【正常路径】【异常路径】【操作角色】【前置条件】【最终状态】。
> 标注「原型-占位」的步骤对应 open-decisions 未确认规则，原型用双态/便签表达，不画成定论。
> 现状基线：扣次发生在**预约创建时**（预扣模式，见 business-rules.md R-B4 / D1）。

---

## 流程 A：学员获卡 → 查看卡 → 预约课程

- **角色**：管理员（发卡）、学员（小程序）
- **前置**：管理员已建卡产品；学员已注册并绑定租户

**正常路径**
1. [admin-web] 卡产品管理 → 创建产品（类型/次数/有效期/适用课程）→ 上架
2. [admin-web] 会员卡管理 → 发放会员卡（选学员+产品，可指定生效日期）→ 卡生成，ISSUE 流水
3. [miniapp] 我的会员卡 → 见到新卡（PENDING 显示"去激活"）
4. [miniapp] 激活 → 状态 ACTIVE，显示剩余次数/有效期
5. [miniapp] 课程列表 → 课程详情 → 选择排期 → **预约确认页（选卡）**→ 默认推荐卡 → 提交
6. 预约成功：BOOKED + CONSUME 流水；确认页与卡列表余额即时减少

**异常路径**
- 5a 卡余额不足：提交报业务错误（信封 code≠0），页面提示"该卡次数不足"，引导换卡 → 终态不变更
- 5b 卡不可用（冻结/过期/不适用该课程）：选卡列表直接过滤或灰显 + 原因文案
- 5c 排期已满/并发冲突：F4.5 保障不双订；提示"名额已满"
- 5d 扣次成功但预约失败（理论不可能，同事务）→ 回滚，无脏数据

**最终状态**：卡 ACTIVE（-1 次）；预约 BOOKED；流水 CONSUME（booking_id 关联）

## 流程 B：学员持多卡 → 选择计划卡 → 预约未来课程

- **角色**：学员
- **前置**：同一学员有多张适用卡（不同产品/有效期）

**正常路径**
1. [miniapp] 预约确认页拉取 my-cards → 过滤出该课程可用卡（类型/适用课程/余额/状态）
2. 系统默认推荐一张（现状：getDefaultSelectedCard 简单规则；"优先消耗先过期"策略 → **D6 原型-占位**）
3. 学员手动切换卡片（单选），页面实时展示所选卡剩余次数与扣次后余额
4. 提交 → 扣所选卡

**异常路径**
- 无可用卡：选卡区空态 + "去查看会员卡"引导（现状空态已有）
- 多卡中部分冻结/过期：灰显 + 原因标签（冻结中/已过期）

**最终状态**：BOOKED 持有被选卡引用；未被选卡零变动

## 流程 C：预约 → 取消 / 改期 → 课卡计划重新校验

- **角色**：学员（自助取消）；改期现状=取消+重约（**D7 原型-占位**）

**正常路径（取消）**
1. [miniapp] 我的预约 → 选 BOOKED 预约 → 取消（填原因，二次确认）
2. 后端：行锁 → 校验可取消（未开始/未签到）→ CANCELLED → RESTORE 回补原卡（同事务）
3. 卡余额即时 +1，流水 RESTORE

**正常路径（改期，原型按两步画并标注 D7）**
1. 取消（回补）→ 重新进入预约确认页选新排期 → 再扣次
2. 原型需展示中间态风险提示："改期将先释放原名额与课时"

**异常路径**
- 取消已签到/已完成的预约：业务错误，状态不变
- 回补目标卡已被作废/删除：现状仍回补到该卡（引用保留）；若卡已删除（FK SET NULL）回补去向未定义 → **D3 关联，原型-占位**
- 改期时新排期已满：提示名额不足，此时旧预约已取消（两步改期的真实风险，原型必须如实展示）

**最终状态**：取消 → CANCELLED + RESTORE；改期 → 旧 CANCELLED + 新 BOOKED

## 流程 D：教师/管理员查看名单 → 签到 →（预扣模式下）核销已成立

- **角色**：教师（teacher-web）/ 管理员（原型新增管理端名单页）；后端权限 `booking:manage`
- **前置**：预约为 BOOKED；扣次已在预约时发生（**D1 决定此页语义**）

**正常路径（现状=预扣模式）**
1. [teacher-web] 我的排期 → 某排期 → 学员名单（bookingApi.list，含状态）
2. 对 BOOKED 学员点击"签到" → CHECKED_IN（行锁，F2.3 防重复签到）
3. 页面提示签到成功；**无扣次动作**（核销已在预约时发生）→ 原型在此处放 D1 便签：若产品改为"签到扣次"，此页增加"扣次结果"反馈与失败态（余额异常/卡失效）

**原型扩展（管理员视角，规划页 S6）**
- [admin-web] 预约管理 → 按排期查名单 → 代签到/代完成（BookingSource=ADMIN 已有枚举支撑）

**异常路径**
- 重复签到：第二次返回业务错误（状态机拒绝），前端提示"已签到"
- 学员未到：现状无"缺席"操作 → **D5 原型-占位**（缺席标记按钮画为灰置"待确认"）

**最终状态**：CHECKED_IN（→ COMPLETED 可选）；卡与流水无变化（预扣模式）

---

## 流程 E：计划课卡失效 → 提示原因 → 替代卡或人工处理

- **角色**：学员、管理员
- **前置**：存在 BOOKED 预约，其计划卡在预约后变为 FROZEN/EXPIRED/CANCELLED
- **现状**：**整条流程未实现**（无重校验、无提示、无替代机制）→ 全流程为原型规划态（**D3**）

**原型-规划路径（推荐方案，待产品确认）**
1. [miniapp] 我的预约列表 → 对失效卡预约显示警示条："计划卡已冻结/已过期/已作废 — 原因"
2. 点开 → 两个出口（原型画双分支）：
   - 出口1 自助换卡：重新拉可用卡列表 → 选替代卡 → 原子改派（依赖 D7 原子改期/改派能力）
   - 出口2 人工处理：展示机构联系方式/提交工单，管理员在后台处理
3. [admin-web] 会员卡管理 → 冲突检查 → 冻结/作废时列出受影响的有效预约（现状 conflict-check 只查卡冲突，预约影响面需扩展 → D3 影响项）

**异常路径**
- 替代卡余额不足：阻断并提示
- 无任何替代卡：仅出口2

**最终状态（规划）**：预约.membership_card_id 改指向替代卡；或维持原状等待人工

---

## 流程 F：卡用尽 / 过期 / 停用 → 对既有预约与后续核销的影响

- **角色**：系统（定时任务）、管理员、学员

**用尽（现状无独立状态 → D2）**
- 原型：卡列表/详情显示"已用尽"徽标（remaining=0 的 ACTIVE 卡）；新预约时该卡被过滤/灰显
- 既有 BOOKED 预约：不受影响（扣次已发生）

**过期（已实现）**
1. [scheduler] expire_at < now 且 ACTIVE → EXPIRED（次卡清零 + EXPIRE 流水）
2. [miniapp] 卡显示"已过期"；选卡列表过滤
3. 既有 BOOKED 预约：现状不处理（学员仍可到店签到）→ **D3/D4 边界，原型-占位**

**停用/作废（已实现）**
1. [admin-web] 作废（必填原因，可批量）→ CANCELLED
2. 既有预约现状不自动取消 → 原型提供两个选项（D3）：a) 提示管理员"该卡有 N 个有效预约"并批量处理；b) 仅提示不处理

**退款**：依赖 F6.1 支付渠道 → 原型仅画入口占位（**D8**），不画定论流程

---

## 流程 G：学员查看实际消费记录 ↔ 管理员查询同一笔核销记录

- **角色**：学员（小程序）、管理员（后台）
- **前置**：任一已发生的 CONSUME/RESTORE 流水

**正常路径（现状数据可得，UI 均为规划页）**
1. [miniapp] 卡详情 → 使用记录（规划页 M7）：流水列表 = 时间/类型（消费/回补/发放…）/关联课程与排期/变动次数/剩余
2. [admin-web] 卡详情（规划页 S4）：同一卡的全量流水 + 操作人（operator_id）+ 幂等键追查
3. 双端同一数据源 `GET /membership/transactions`（card_id 过滤），学员端只看自己的卡（归属校验）

**异常路径**
- 学员查他人卡：403/404（F2.2 归属规则同源）
- 流水为空：空态四件套

**最终状态**：两端展示同一笔流水的对齐视图（字段口径见 interaction-spec.md S4/M7）

## 流程总览

```
A 发卡→激活→预约(扣次)      B 多卡选计划卡             C 取消(回补)/改期(D7)
        │                        │                        │
        ▼                        ▼                        ▼
   BOOKED ──────────────► D 教师签到(CHECKED_IN, 无二次扣次 D1)
        │                                             │
        │ E 卡失效→提示→替代(D3, 规划态)               │
        ▼                                             ▼
   F 用尽/过期/停用对预约影响(D2/D3/D8)         G 双端查同一笔流水
```
