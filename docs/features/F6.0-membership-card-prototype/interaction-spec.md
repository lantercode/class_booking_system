## 通用约束（所有页面）

- 四态必备：loading / empty / error(403/409/500) / success（F3.4 基线）
- 业务错误以信封 `code≠0` + `msg` 呈现，HTTP 200 不代表成功
- 写操作（发卡/冻结/作废/取消预约/签到）一律二次确认
- 管理端操作显示操作人（operator）与原因必填项（作废/冻结）

- **端/角色**：admin-web / 管理员
- **入口**：侧边栏"卡产品管理"；**出口**：无（列表页）

## P-A6 排期签到点名（规划）

- **端/角色**：admin-web / 管理员（booking:manage）
- **入口**：P-A5 按排期进入；**出口**：返回
- **展示字段**：名单=学员、预约状态（与 P-A5 同一状态字典：已预约/已取消/已签到/已完成/未到场）、会员卡、签到时间
- **操作**：代签到（BOOKED→CHECKED_IN，二次确认，**校验计划卡状态非 ACTIVE 则拦截——D9**）、完成（CHECKED_IN→COMPLETED）；缺席不设手动按钮（D5：排期 COMPLETED 即扣、自动消解）
- **决策占位**：签到后无扣次反馈文案按现状（D1）；若 D1 改签到扣，此页加扣次结果区
- **失败**：重复签到→提示"已签到"；排期未开始→业务错误；**计划卡已过期/作废→提示卡状态异常（D9）**
- **API**：`GET /bookings?schedule_id=`、`POST /bookings/{id}/check-in`、`POST /bookings/{id}/complete`
- **验收**：并发演示：两名管理员同时点同一学员签到，仅一次成功（F2.3 行锁）；**计划卡非 ACTIVE 时签到被拦截（D9）**

- **展示字段**：排期摘要；可用卡单选列表（产品名/类型/剩余次数/适用标签/**预期有效期——D9**）；所选卡扣次后余额预览
- **操作**：切卡（单选）；默认选中按推荐策略（**D6 占位：先过期优先**）；提交（写操作二次确认）
- **D9 选卡规则**：按"排期日 + validity_days"计算预期有效期，与已有同课程类型卡做区间重叠冲突检查；PENDING 卡正常可选（角标"待激活"）；冲突卡灰显"与已有卡有效期重叠"
- **失败**：余额不足/卡不可用/名额满 → 分类错误文案；**预期有效期与已有卡重叠→该卡灰显并提示"与已有卡有效期重叠"（D9）**；无可用卡→空态+引导
- **跨排期时间段冲突（D10，确认阶段拦截）**：**触发**：目标排期时间段与该学员已有「进行中」预约（BOOKED/CHECKED_IN，不含 CANCELLED/COMPLETED）所在排期时间段重叠（口径 `a.start < b.end && b.start < a.end`）；**行为**：点击「确认预约」时不进入写操作、不生成新预约、不改动任何既有预约状态；**文案**：`该时间段与您已约课程《课程名》冲突（目标时段 与 已约时段），无法预约`（含冲突课程名与两个时间段）；**异常反馈**：toast 提示，停留当前页。与「会员卡有效期重叠」拦截**相互独立**、互不覆盖（命中卡冲突时优先提示卡冲突）。原型演示数据：目标排期 S6（19:30-20:30）与已约排期 S1（19:00-20:30）重叠。
- **状态变化**：BOOKED + 次卡 CONSUME 预扣（同事务）；期卡不扣次，排期 COMPLETED 时激活（D9）
- **API**：`GET /membership/my-cards`、`POST /bookings/`（body: schedule_id + membership_card_id）
- **验收**：多卡切换后提交，扣的是最终选中卡；余额预览与提交后一致；**卡二预期有效期与卡一重叠时被过滤不可选（D9）**；**PENDING 卡（预期有效期不冲突）可选并成功预约（D9）**；**跨排期时间段重叠的目标排期被拦截且不生成新预约（D10）**
