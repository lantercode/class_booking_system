## 需求 A：用户头像 / 图片存储

### D-F7-A1 图片存储方案（本地 / OSS / 直传）

- **现状**：`upload` 模块为空壳，无任何上传能力；生产部署为 Docker + Docker Compose + Nginx + 阿里云 ECS。
- **推荐方案：方案 B（阿里云 OSS 对象存储）+ 后端签发短期凭证的受控上传**（见 solution-design.md 第四节详评）。理由：容器重建后文件持久（本地方案在容器重建/多副本时丢文件）、可挂 CDN、多租户可用前缀隔离、ECS 磁盘零占用。
- **备选方案**：A 本地文件存储（开发期够用，生产不可靠，容器重建丢文件）；C 客户端受控临时凭证**直传** OSS（省后端带宽，但需前端承担校验与失败重试，Web 三端 + 小程序四端实现成本高、安全面更大）。
- **原型默认**：以**方案 B 的服务端中转上传**呈现交互（前端只调 `POST /upload/image`，不同步实现直传）。
- **影响面**：上传接口设计、`FileObject` 数据模型、前端上传组件、部署（OSS bucket/权限/密钥）。

### D-F7-A2 数据库存什么（URL / object key / 文件记录）

- **现状**：`users.avatar_url = String(500)`（存 URL）。`classrooms` 无图片字段。
- **推荐方案：业务表存 `object_key`（或 URL 路径），URL 由后端按环境拼装（`avatar_url = 后端依据 key 生成`）**；复杂附件另建 `file_objects` 记录表（`id/tenant_id/object_key/mime/size/uploader_id/created_at`）。理由：换域名/CDN 时不必刷库；租户隔离前缀可审计；清理有据可查。
- **备选方案**：仅存完整 URL（简单但迁移/换 CDN 需全量刷库）。
- **影响面**：用户/教室 DTO、迁移脚本、图片清理任务。

### D-F7-A3 上传接口归属（FastAPI 中转 vs 直传）

- **推荐方案：FastAPI 中转 `POST /api/v1/upload/image`**（后端做四关校验 + 类型/大小/租户校验 + 写 OSS + 落 `file_objects`）。理由：符合项目「后端是唯一权威方」与 MCP/Tool 分层规则；Web 三端共用 api-client 零改造；安全边界集中。
- **备选方案：直传**（须前端先调 `POST /upload/presign` 拿临时凭证，再由客户端 PUT 到 OSS）。
- **影响面**：上传时延、后端带宽、前端复杂度。

### D-F7-A4 上传约束（类型 / 大小 / 比例）

- **现状**：无。小程序 banner 现用 `unsplash` 图（16:9 横图）；视频封面 16:9。
- **推荐方案**：允许 `image/jpeg,image/png,image/webp`；**单文件 ≤ 5MB**；头像强制方形裁切（≥200×200），banner/封面按 16:9 裁切；超限/类型不符返回友好错误。
- **影响面**：前端裁剪组件、后端校验、错误文案。

### D-F7-A5 新增用户时是否允许上传头像

- **现状**：新增用户弹窗无头像项。
- **推荐方案：允许**（先上传拿 `avatar_url`，再随 `POST /users/` 提交；`UserCreate.avatar_url` 已支持）。
- **备选**：仅编辑时上传。
- **影响面**：新增弹窗布局、提交时序（先传图后提交）。

## 需求 B：个人资料

### D-F7-B1 个人资料可编辑字段范围

- **现状**：`PATCH /auth/me` 白名单 = **仅 `nickname` + `avatar_url`**（`auth/service.py:63`）。
- **推荐方案：保持现状**——个人资料弹窗仅开放「头像 + 昵称」两个可编辑项，手机号/角色/租户**只读展示**。
- **备选**：额外开放真实姓名/性别/生日（需后端扩白名单，会牵动 `users` DTO 与其它端）。
- **影响面**：弹窗字段、后端白名单、`adminInfo` 结构（当前 `adminInfo` 仅 `nickname/avatar/phone/roles`）。

### D-F7-B2 手机号能否自助修改

- **现状**：`PATCH /auth/me` **不接受 phone**；改手机号会使登录凭据变更，涉及唯一约束 `uq_users_tenant_phone`（`user/models.py:50-57`）。
- **推荐方案：不允许自助修改**，手机号在弹窗中**只读**；如需修改走管理端用户编辑（当前也是 disabled 只读）。
- **备选**：开放「换绑手机号」（需新验证码流程）。
- **影响面**：登录/绑定链路、唯一约束、找回密码。

### D-F7-B3 个人资料是否含「修改密码」入口

- **现状**：`POST /users/{id}/password/change` 端点存在（用户自己改，需旧密码）。
- **推荐方案：本阶段弹窗不放改密码**（保持最小范围），仅记入口占位。
- **影响面**：弹窗范围。

## 需求 C：教室

### D-F7-C1 教室新增字段（封面图 / 位置 / 编码）

- **现状**：`classrooms` 表**仅** `name/equipment/status`（`course/models.py:18-30`）；无图片、无编码、无位置、无容量。
- **推荐方案：新增 `cover_image_url`（必需 + 封面图上传）、`location`（字符串，可空）、`code`（教室编码，租户内唯一，必填）**；**原「容纳人数 `capacity`」字段已删除、不再引入**。
- **备选**：无（原「编号暂不引入」备选已否决，编码改为已确认引入，见 `D-F7-C3`）。
- **影响面**：DB 迁移、教室 DTO、卡片/弹窗 UI、排期关联展示、`code` 唯一约束。
- **原型默认**：卡片按「教室编码 + 封面图 + 位置」呈现；`location` 以「待评审」灰标占位，`code` 为已确认字段（必填 + 唯一性校验）；**封面图未设置 / 图片失效时统一回落「暂无图片」占位**（不绘制默认封面图，`D-F7-E7`）。

### D-F7-C2 教室页面视图形态（表格 / 卡片）

- **现状**：仅卡片网格。
- **决策（2026-10-19，产品确认）**：**仅保留卡片视图，不提供表格（列表）视图**，也不提供「表格 ⇄ 卡片」视图切换。理由：教室为图片型实体，卡片视图信息表达更直观；避免双视图带来的结构/分页/批量操作归属复杂度。
- **已否决的备选**：表格 + 卡片双视图并存（默认表格）。
- **影响面**：页面结构（单视图卡片网格）、分页/批量操作归属（本阶段无批量操作）。
- **原型落地**：`prototype/index.html` 教室管理 `P-F7-05` 已移除表格视图渲染与切换控件（`.seg`）、移除 `STATE.classroomView` 与 `toggleClassroomView`。

### D-F7-C3 教室「编号」语义

- **现状**：无编号字段。
- **决策（2026-10-19，产品确认）：已确认引入**「教室编码 `code`」——采用与现有 `user_code/teacher_code/student_code` 同风格的租户内短码（如 `R-001`），**必填且租户内唯一**；新增/编辑保存时做唯一性校验，重复则报「教室编码已存在」。
- **影响面**：DB 新增 `code` 列 + 唯一约束、教室 DTO、卡片/表格/弹窗展示与保存校验。

## 需求 D：首页管理

### D-F7-D1 一级导航最终命名

- **现状**：现有导航为业务域命名（用户管理/教室管理/…），无「装修」类词。
- **推荐方案：一级导航命名「小程序首页」**（与现有「XX 管理」中性命名一致）；页面内标题「小程序首页配置」。
- **备选**：`小程序装修`（偏运营术语）。
- **影响面**：导航文案、路由 `/miniapp-home`。

### D-F7-D2 模块排序交互

- **现状**：无（首页模块顺序现为硬编码）。
- **决策（2026-10-19，产品确认）**：模块配置新增 **排序字段 `sort`**（1 最靠前，连续整数），后台管理端支持**拖动排序**（HTML5 原生 drag，无需引入拖拽库；`dragstart/dragover/drop` 事件，放下后重写 1..n 连续排序值）。模块行同时展示排序值徽标与拖拽手柄；保留程序化上/下移动函数作为键盘/无障碍与脚本驱动兜底（底层复用同一重排逻辑）。
- **已否决的备选**：仅"上下移动按钮"（体验较差，不足以直观表达"排序字段"）。
- **影响面**：前端组件（拖拽交互）、排序落库方式（`sort_order` 连续整数、拖拽后整体重写）。
- **后续实现注意**：真实实现建议采用拖拽库（如 `vuedraggable`）+ 后端 `PATCH /home/config/draft/reorder` 批量提交新顺序，避免逐条请求；拖拽过程不得整页重渲染（会打断原生 drag），原型已按此约束实现。

### D-F7-D3 模块是否允许增删

- **现状**：无。
- **推荐方案：第一阶段模块类型固定 5 种，**不新增/删除模块类型**，只允许启用/停用与排序**。
- **备选**：允许同类型多实例（如多个 banner 模块）。
- **影响面**：数据模型（`module_type` 唯一性）。

### D-F7-D4 师资/课程「内容选择」方式

- **现状**：小程序师资来自 `GET /teachers`、推荐课程来自 `GET /courses`（真实 API，已可用）。
- **推荐方案：手动选择 + 展示数量**（管理端从教师/课程列表勾选最多 N 个，按选择顺序展示）；**不引入自动推荐算法**（无数据支撑）。
- **备选**：按规则自动推荐（需销量/热度数据，当前无）。
- **影响面**：配置表单字段、复用现有 teachers/courses API。

### D-F7-D5 舞蹈视频来源

- **现状**：小程序 video 为硬编码 `{title,description,duration,coverUrl,videoUrl}`。
- **推荐方案：封面图上传 + 视频地址 URL（外链）**，第一阶段不做视频文件托管（避免大文件 OSS 流量成本）。
- **备选**：视频文件上传托管。
- **影响面**：配置表单、OSS 成本、播放器兼容。

### D-F7-D6 Banner 跳转目标类型

- **推荐方案：枚举 `课程详情 / 课程列表 / 视频 / 无跳转`**（对应小程序现有路由 `courses/detail`、`courses/list`、`videos/player`）。
- **影响面**：配置表单、小程序路由映射表。

## 需求 E：首页数据流

### D-F7-E1 草稿与已发布是否分离

- **现状**：无。
- **推荐方案：**分离**——后台维护 `draft`（草稿），发布时**整份快照**写入 `published`（带版本号 + 发布时间 + 操作人）。小程序只读 `published`。改草稿**不影响**线上。
- **备选：单份配置 + `is_published` 标记（简单但无法"改草稿不影响线上"）。
- **影响面**：数据模型（草稿表 + 发布版本表）、发布接口、小程序读取接口。

### D-F7-E2 发布失败是否保留旧版本

- **推荐方案：**保留**——发布为**原子操作**（校验通过才写 `published`）；失败则 `published` 不变，旧版本继续对外，返回可读错误。
- **影响面**：发布事务、回滚策略、前端错误提示。

### D-F7-E3 小程序请求失败降级

- **推荐方案：**分级降级**——接口失败时，能走真实 API 的模块（师资/课程）继续用真实 API；纯配置模块（banner/video/公告）用**本地缓存副本**，无缓存则**隐藏该模块**，不报错白屏。
- **影响面**：小程序首页渲染逻辑、本地缓存策略。

### D-F7-E4 模块为空 / 停用的展示

- **推荐方案：**静默隐藏**——模块未配置内容或未启用时，小程序**不渲染该模块**（不显示空壳标题）。
- **影响面**：渲染分支、预览态提示。

### D-F7-E5 首页接口是否需租户上下文

- **推荐方案：**必须**——`GET /miniapp/home/published` 走 `x-tenant-slug` + `TenantAwareRepository`，已发布配置按 `tenant_id` 隔离。
- **影响面**：接口鉴权、租户隔离测试。
- **备注**：该接口面向小程序（学员已登录），沿用现有鉴权链；是否允许游客访问需产品确认（见 D-F7-E6）。

### D-F7-E6 首页接口访问权限

- **推荐方案：登录学员可访问**（沿用 `get_current_user`）；**不开放游客访问**（当前小程序首页内容亦在登录后）。
- **影响面**：鉴权依赖、缓存 key。

### D-F7-E7 图片失效占位

- **推荐方案：统一占位图**（banner/封面/头像各一套中性占位），图片 `onerror` 回退占位，不出现破图。
- **原型落地**：教室封面**未设置**（`cover` 为空）与封面**加载失败/失效**（`BROKEN`）**统一显示「暂无图片」占位**——已按用户要求回退并**删除 `roomDefaultCover()` / `IMG.ROOM_DEFAULT`**，未设置封面不再绘制默认封面图（`coverTag` 无图直接返回占位）。
- **影响面**：前端组件、占位资源。
