## 3. 基线画像（跨样本结论）

1. **活跃耗时与风险等级正相关且稳定**：L3 ≈6–28 min，L4 ≈55–73 min。等级声明（M1）在基线下已被实际使用且区分度良好。
2. **等待时间是 wall_clock 主导项**：F6.3 等待占 95%、F6.5 占 77%；活跃耗时仅占小头。**优化对象应是活跃耗时与返工，而非等待**；遥测模板已把等待单列，口径有效。
3. **L3 任务的成本大头是流程而非代码**：F6.4 实现仅 2 min，产物 + 验证 + 决策约 4 min；F6.6 实现 8 min，Review + 文档 12 min。**L3 的 9 份产物是相对代码量最大的开销**——直接支持 M1「分级产物」方向。
4. **返工全部可归因，且发现时点有规律**：
   - 真实并发缺陷（F6.3 R2、F6.5 R1/R4）都在**测试或 Review/验收阶段**才暴露——基线流程缺「并发设计前置校验」，支持 M5 测试分层中「并发场景强制专项」的保留项。
   - F6.6 的 3 处返工全部在**规划阶段被 Architect 复核拦截**，实现/测试阶段零返工——证明「规划复核前置」能把返工移到最便宜的位置。
   - lint / 迁移漂移类返工（F6.3 R3、F6.5 R2/R3）成本极低（自动修复 / alembic check 拦截），不构成优化重点。
5. **工具可靠性问题真实存在**：F6.3 R1 子 Agent 首次调用返回缺失，造成 1060 min 中断（用户侧等待）；提示词精简后恢复。属平台/协作健壮性问题，M 系列未覆盖，建议登记为独立改进项。
6. **遥测模板缺口**：子 Agent 工具调用数、读取行数普遍 UNKNOWN（F6.3 已显式声明）；阶段边界多处为事后估算。模板需加「子 Agent 必须回传工具调用数与阶段边界」字段。
7. **安全底线达标**：四样本 0 安全/租户/权限缺陷；§9.2 的否决项（任何 1 例即失败）在基线侧成立。
