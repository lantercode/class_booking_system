## 8. 结论与观察

- **两处契约偏差已在实施中发现并处理**：
  1. `create_booking` 响应不回填卡字段（`card_type/remaining_credits` 为 None）→ 结果页改由 `getCardDetail` 拉取真实余额，card_type 由确认页 query 透传；拉取失败降级为「已预扣 1 次」不显示剩余。
  2. 需求文档称名额满/时间重叠为 409，后端实际统一 400 → 前端按 statusCode + msg 关键词分类（约满/重叠→选其他排期；余额/卡→换卡重试；其他→稍后重试）。
- **失败态选择**：跳结果页（而非 toast 停留），否则结果页失败态在真实流程不可达；401 不跳转（API 层统一处理）。
- **建议后续后端 Feature 评估**（非本期范围）：`create_booking`/`get_booking` 回填卡关联字段；错误码 400/409 语义与需求文档对齐。
- 最耗时环节：无（单 Agent 一次交付）；无重复读取；无返工。
